## Plan (written before coding)
- Implement `BaseModelRoutingProvider`, `RoutingDecision`, `RoutingHints`, `RoutingRecord`, `TaskCategory`, `TargetBackend`, `LatencyBudget`, and `CostSensitivity` in `sidecar/providers/model_routing.py`.
- Re-export model routing provider contracts in `sidecar/providers/__init__.py`.
- Implement `ModelRoutingProvider` in `sidecar/model_routing.py`:
  - `classify`: classifies `hint:quick`/`hint:fast` -> Lightweight, `hint:medium` -> Medium, `hint:reasoning`/`hint:agentic`/`hint:coding`/`hint:chat` -> Heavy, explicit models -> Heavy.
  - `decide`: evaluates category, local health, hints, and tools override (tools force remote; privacy_required forces local, fails closed with no fallback, disables streaming).
  - `check_local_health`: cached probe with 30-second TTL and 3-second timeout with lock discipline (release lock before network probe).
  - `is_low_quality`: allocation-free heuristic checking length floor (< 10 bytes), empty-noise tokens ("...", "I", "", "?"), and refusal DFA patterns.
  - `execute_routed_chat`: primary execution with remote fallback on local failure and quality gate fallback on refusal.
  - Register provider in registry under `("model_routing", "default", ModelRoutingProvider)` and alias `("intelligent_model_routing_quality_based_fallback", "default", ModelRoutingProvider)`.
- Implement TypeScript extension routing module in `locus-extension/src/routing/` (`types.ts`, `policy.ts`, `health.ts`, `quality.ts`, `router.ts`, `index.ts`), and re-export in `locus-extension/src/index.ts`.
- Add routes `/routing/decide`, `/routing/health`, `/routing/quality-check`, and `/routing/config` in `sidecar/service.py` with 503 off-switch on `locus.intelligent_model_routing_quality_based_fallback.enabled`.
- Unit tests in `tests/unit/test_model_routing.py` and integration tests in `tests/integration/test_model_routing_service.py`.
- Pi table:
  - Need: In-process policy layer to route requests between local model servers (Ollama/LM Studio) and remote backends, with quality-based fallback for refusals and privacy-required fail-closed guarantees.
  - Pi mechanism: Pi provides model resolution and virtual models (`packages/coding-agent/src/model-resolver.ts`), but lacks dynamic local/remote task classification, 30s TTL health caching, tool-use routing overrides, refusal DFA detection, and quality-triggered fallback dispatch.
  - What Locus adds: Full OpenHuman-derived routing engine with 3-category classification, latency/cost hints, privacy mode fail-closed enforcement, local health caching, refusal DFA heuristic, and telemetry recording.
  - Why Pi's is not enough: Pi's model resolver statically resolves configured strings and cannot dynamically pivot between local Ollama and remote APIs based on runtime health, complexity hints, or response quality.
