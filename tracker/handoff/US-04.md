## Security (anything found, even if outside this story)
- Replaced vulnerable legacy "first-touch auto-pairing" (where the first stranger messaging the bot claimed ownership) with cryptographically secure one-time pairing per S-1.
- All pairing codes are 10 uppercase characters/digits generated via Python's `secrets` module.
- Plaintext codes are displayed only on the local machine running setup and never stored in memory; only SHA-256 hashes are held.
- 5 wrong attempts trigger an automatic 15-minute lockout.
- Allowed owner Telegram ID is strictly numeric (never user handles).
- Corrupted or unreadable configuration triggers immediate fail-closed state.

## Sprint Review Live Demo Instructions (for Owner)
With a test Telegram bot token:
1. On the PC running Locus:
   `py -3 -m locus_cli.setup_telegram`
   Output shows: `One-time pairing code: <CODE> (valid for 10 minutes)`.
2. From a stranger/second Telegram account, send `hello` to the bot:
   - Expected bot response: `not configured`
3. From your personal Telegram account, send `/pair <CODE>`:
   - Expected bot response: `Paired successfully. You are now the owner of this Locus instance.`
4. From the stranger account, send `/pair <CODE>`:
   - Expected bot response: `No active pairing code. Run pairing setup on the host machine.`
5. Restart the bot/sidecar:
   - Send `ping` from your account -> bot recognizes owner.
   - Send `ping` from stranger account -> bot answers `not configured`.
