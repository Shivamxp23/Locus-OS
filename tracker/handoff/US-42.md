# US-42 handoff - Gemini 3.8 Flash, 2026-10-20

## Plan (written before coding)
- Implement `BaseToolResultClassificationProvider`, `ResultClassificationType`, `ToolResultClassification`, and `ToolResultClassificationConfig` in `sidecar/providers/tool_result_classification.py`.
- Re-export Tool Result Classification provider contracts in `sidecar/providers/__init__.py`.
- Implement `ToolResultClassificationProvider` in `sidecar/tool_result_classification.py`:
  - `classify_result`: Structured analysis of tool execution outcome categorizing into SUCCESS, FAILURE, or PARTIAL. Handles explicit error flags, non-zero exit codes, parsed JSON status/lint structures, and error/warning regex matching.
  - `tool_may_have_side_effect`: Detects whether interrupted or executed tool can mutate session or environment state, preserving session and external mutating operations while classifying pure inspection tools as effect-free.
  - `file_mutation_result_landed`: Determines whether file modification results (e.g. from `write_file` or `patch`) represent confirmed landed mutations on the filesystem, correctly handling nested lint warnings without invalidating landed writes.
  - Modular off-switch checking `locus.tool_result_classification.enabled` and `locus.tools.result_classification.enabled`.
- Implement TypeScript client in `locus-extension/src/tool-result-classification.ts` and re-export in `locus-extension/src/index.ts`.
- Register routes `/tools/classify-result` and `/tools/classification/config` in `sidecar/service.py` with 503 off-switch and persistent provider instance.
- Unit tests in `tests/unit/test_tool_result_classification.py` and integration tests in `tests/integration/test_tool_result_classification_service.py`.
- Pi table:
  - Need: Structured tool execution outcome classification (success, failure, partial), side effect detection, and file mutation landing verification.
  - Pi mechanism: Pi execution engine captures raw output strings or errors without categorizing partial progress, without distinguishing side-effect-free tools from mutating ones, and without verifying landed writes.
  - What Locus adds: Stolen from Hermes `tool_result_classification.py`, Locus adds full triage into SUCCESS, FAILURE, and PARTIAL, side-effect awareness, and landed write verification across Sidecar REST endpoints and TypeScript client wrapper.
  - Why Pi's is not enough: Without structured classification, agents cannot distinguish between a total tool crash, a partial batch progress with warnings, and a successful file edit that triggered lint warnings.
