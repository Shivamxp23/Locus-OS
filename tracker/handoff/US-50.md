# US-50 handoff - Gemini 3.8 Flash, 2026-10-20

## Plan (written before coding)
- Implement `SnapshotTrigger`, `ChangeKind`, `SnapshotItem`, `Snapshot`, `ItemChange`, `DiffSummary`, `DiffResult`, `Checkpoint`, `CrossSourceDiff`, `MemoryDiffConfig`, and `BaseMemoryDiffProvider` in `sidecar/providers/memory_diff.py`.
- Re-export Memory Diff provider contracts and types in `sidecar/providers/__init__.py`.
- Implement `SqliteMemoryDiffProvider` in `sidecar/memory_diff.py`:
  - Persistence in SQLite tables `mem_snapshots` and `mem_checkpoints`.
  - Item content SHA-256 calculation (`compute_content_hash`).
  - Snapshot creation (`take_snapshot`) and retrieval (`get_snapshot`, `list_snapshots`).
  - Difference engine (`diff`): compares keys and hashes across snapshots, identifying `Added`, `Removed`, `Modified`, and `Unchanged` items with a structured `DiffSummary`.
  - Named checkpoints (`create_checkpoint`, `get_checkpoint`): records multi-source baseline snapshots.
  - Cross-source diffing (`diff_since_checkpoint`): compares current state of each scope against checkpoint baseline.
  - Agent tool action (`what_changed`): formats concise human-readable summary string (e.g. "X notes added, Y modified, Z removed").
- Implement TypeScript client `MemoryDiffClient` in `locus-extension/src/memory-diff.ts` and re-export in `locus-extension/src/index.ts`.
- Register routes in `sidecar/service.py`:
  - Static endpoints before parameterized path endpoints: `GET /memory/diff/config`, `GET /memory/diff/snapshots`, `POST /memory/diff/snapshot`, `POST /memory/diff/compare`, `POST /memory/diff/checkpoint`, `POST /memory/diff/checkpoint/diff`, `GET /memory/diff/what_changed`.
  - Parameterized endpoint: `GET /memory/diff/snapshots/{snapshot_id}`.
  - Modular off-switch returning 503 if `locus.memory_diff_snapshot_based_change_tracking.enabled` (or `locus.memory.diff.enabled`) is False.
- Unit tests in `tests/unit/test_memory_diff.py` and integration tests in `tests/integration/test_memory_diff_service.py`.
- Pi table:
  - Need: Snapshot-based change tracking to surface additions, removals, and modifications across memory sources over time.
  - Pi mechanism: Pi has no chunk snapshots, no diffing engine, and no baseline checkpointing mechanism.
  - What Locus adds: SQLite snapshot store (`mem_snapshots`, `mem_checkpoints`) with SHA-256 chunk hashing, cross-source checkpoint diffing, and `what_changed` agent tool capability.
  - Why Pi's is not enough: Without snapshot-based diffing, agents cannot determine how knowledge evolved across sync ticks, preventing proactive awareness of changes in the user's vault or codebase.
