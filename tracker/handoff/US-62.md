- Pi table:
  - Need: Command-line interface and diagnostic health inspection across multi-surface interfaces (CLI, Telegram, Pi TUI, and Headless VM daemons).
  - Pi mechanism: `packages/coding-agent/src/cli.ts:1-200` provides Pi's command-line parsing and entry point for interactive sessions and subcommands (`--help`, `--version`, flags).
  - What Locus adds: Unified `locus` CLI in `locus_cli/main.py` routing commands (`run`, `setup`, `config`, `doctor`, `gateway`, `cron`, `life`, `vault`, `memory`), modular multi-subsystem doctor diagnostic probes in `locus_cli/doctor.py` and sidecar `/system/doctor`, configuration management in `locus_cli/config.py`, and provider abstraction in `sidecar/providers/cli_doctor_diagnostics.py` with 503 off-switch.
  - Why Pi's is not enough: Pi's CLI is solely designed for the interactive coding harness and cannot manage the self-hosted Locus cognitive architecture (Telegram bot daemon, couchdb sync, background cron scheduler, neo4j memory, or multi-surface configuration sync).
