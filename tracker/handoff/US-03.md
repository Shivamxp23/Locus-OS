## Security (anything found, even if outside this story)
- All database and backend service ports (5984, 7687, 5432, 6379, 8420) are bound to `127.0.0.1`, completely preventing unauthorized network exposure on public interfaces or local Wi-Fi.
- CouchDB admin password is required via environment interpolation and cannot be defaulted to an insecure hardcoded string.
- CouchDB CORS origins restricted explicitly to `app://obsidian.md`, `capacitor://localhost`, `http://localhost`.

### Admin Password Rotation on Existing Data Directory
Greenfield installations require no migration commands because `data/` does not yet exist and CouchDB creates the admin user from `COUCHDB_USER` and `COUCHDB_PASSWORD` on its first boot.
For an existing deployment where a data directory already exists, CouchDB hashes and stores credentials in its local configuration, ignoring subsequent changes to `COUCHDB_PASSWORD`. To rotate the admin password on an existing database:
1. Online rotation via CouchDB HTTP API:
   ```bash
   curl -X PUT http://127.0.0.1:5984/_node/nonode@nohost/_config/admins/admin \
     -u "admin:<current_password>" \
     -d '"<new_password>"'
   ```
2. Offline / direct configuration rotation:
   Append the new plaintext password under `[admins]` in the local config file:
   ```ini
   [admins]
   admin = <new_plaintext_password>
   ```
   Upon container restart, CouchDB reads the plaintext string, hashes it with PBKDF2 in place, and stores the salted hash.
