- Re-export symbols in `sidecar/providers/__init__.py`.
- Implement TypeScript contract `ArchitectClient`, `ArchitectCandidate`, and scan/apply interfaces in `locus-extension/src/architect/client.ts`.
- Mount FastAPI endpoints in `sidecar/service.py`:
  - `POST /architect/scan`: gathers signals and proposes improvement candidates.
  - `GET /architect/candidates`: lists proposed/staged candidate patches.
  - `POST /architect/apply`: applies or stages candidate by ID based on risk gate.
  - `GET /architect/history`: returns history of recorded patch outcomes.
  - Off-switch returning HTTP 503 if Architect Bot is disabled.
- Write unit tests in `tests/unit/test_architect.py` and integration tests in `tests/integration/test_architect_service.py`.
- Pi table:
  - Need: Proactive self-improvement loop analyzing system signals, proposing risk-gated patches to runtime operating artifacts (SOUL.md, config.yaml), and delegating code bugfixes to external coding harnesses.
  - Pi mechanism: Upstream Pi operates entirely reactively per turn with static prompts and static configuration (`packages/coding-agent/src/index.ts`).
  - What Locus adds: Full self-evolving architect engine in `sidecar/architect/engine.py`, `sidecar/providers/architect.py`, and `locus-extension/src/architect/client.ts` with multi-signal analysis, target classification, risk gating, and REST endpoints with 503 off-switch.
  - Why Pi's is not enough: Pi has no background self-evaluation loop or mechanism to propose self-modifications to its prompts or configuration based on aggregated reward and experience trajectories.
