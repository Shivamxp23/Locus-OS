# US-26 handoff - Gemini 3.8 Flash, 2026-10-20

## Plan (written before coding)
- Implement `BasePostTurnProvider`, `PostTurnReviewResult`, `SkillUpdatePreference`, and `ALLOWED_REVIEW_TOOLS` in `sidecar/providers/post_turn.py`.
- Implement `PostTurnReviewer` in `sidecar/learning/reflector.py`:
  - Daemon thread execution (`spawn_background_review` uses `threading.Thread(..., daemon=True)` and does not block the caller).
  - Strict tool whitelist: permits only `memory`, `skill_manage`, `locus_memory`, `locus_vault`; denies all other tools (`bash`, `write_file`, `browser`, etc.).
  - Combined review prompt (`build_review_prompt` merges memory review and skill review).
  - 4-tier skill preference hierarchy (`UPDATE_CURRENTLY_LOADED`, `UPDATE_EXISTING_UMBRELLA`, `ADD_SUPPORT_FILE`, `CREATE_NEW_UMBRELLA`).
  - "Never fatal" error containment (exceptions logged, never crash caller or conversation session).
  - Swappable off-switch (`locus.post_turn_review.enabled`).
- Implement TypeScript integration in `locus-extension/src/post-turn-reviewer.ts` and re-export in `locus-extension/src/index.ts`.
- Register routes `/review/post-turn`, `/review/tools/allowed`, `/review/skills/preferences`, `/review/result/{review_id}` in `sidecar/service.py` with 503 off-switch on `locus.post_turn_review.enabled`.
- Unit tests in `tests/unit/test_post_turn_review.py` and integration tests in `tests/integration/test_post_turn_review_service.py`.
- Pi table:
  - Need: Post-turn memory and skill extraction. Pi mechanism: Extension hooks `turn_end` / `agent_end`. What Locus adds: Daemon-thread background review executing in separate thread with restricted tool whitelist without competing with foreground prompt cache. Why Pi's is not enough: Pi has no background agent review mechanism; synchronous post-turn processing blocks user interactive latency.
  - Need: Tool sandboxing during review. Pi mechanism: None (all tools available). What Locus adds: Strict whitelist denying execution/filesystem tools (`bash`, `write_file`, `browser`) to prevent side-effects during automated review.
  - Need: Safe fault containment. Pi mechanism: Extension errors bubble up. What Locus adds: "Never fatal" error isolation so review failure never interrupts the user session.

## Security (anything found, even if outside this story)
- Strict whitelist blocks filesystem modification (`write_file`, `edit_file`) and shell execution (`bash`, `terminal`) during autonomous background review.
- Review endpoints bind strictly to loopback (`127.0.0.1`), never `0.0.0.0`.
- All endpoints enforce the 503 off-switch when disabled.
