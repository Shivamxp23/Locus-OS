# US-07 handoff - Gemini, 2026-10-15

## Plan (written before coding)
1. Implement `TelegramChannelProvider` in `sidecar/channel_telegram.py` adhering to `ChannelProvider` interface:
   - Register under `('channel', 'telegram')` in `ProviderRegistry`.
   - Read configuration via `sidecar.config` (`locus.channel.telegram.enabled`, `locus.channel.telegram.token`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_URL`, `TELEGRAM_WEBHOOK_SECRET`).
   - Obey feature enabled toggle: when `locus.channel.telegram.enabled` is false, connection and polling are inactive.
   - Enforce fail-closed webhook validation: if `TELEGRAM_WEBHOOK_URL` is set, `TELEGRAM_WEBHOOK_SECRET` is mandatory.
   - Integrate with `TelegramPairingManager`:
     - Verify sender against paired owner ID.
     - Reject/ignore unpaired senders with fixed string without executing code or leaking system details.
     - Process `/pair <code>` for initial owner pairing.
   - Dispatch paired owner messages to `run_pi_turn`:
     - Maintain persistent per-chat session ID `telegram_<chat_id>`.
     - Forward response to `send_message(chat_id, response_text)`.
     - Chunk messages exceeding 4096 characters to comply with Telegram API constraints.
   - Implement `health_check()` reporting status (`ok`, `disabled`, `down`), latency, and error details.
2. Implement unit tests in `tests/test_channel_telegram.py`:
   - `test_telegram_channel_registration`: Provider registers under `('channel', 'telegram')`.
   - `test_telegram_channel_disabled_behavior`: When enabled is false, does not connect or poll.
   - `test_telegram_channel_paired_owner_triggers_pi`: Inbound message from owner invokes `run_pi_turn` with `telegram_<chat_id>` and replies.
   - `test_telegram_channel_unauthorized_sender_rejected`: Messages from unknown chat/user IDs are rejected without running Pi.
   - `test_telegram_channel_message_chunking`: Long outputs (>4096 chars) are safely chunked.
   - `test_telegram_webhook_secret_required`: Webhook mode fails closed when secret is absent.
   - `test_telegram_channel_health_check`: Health check returns status and latency.
3. Implement integration tests in `tests/test_channel_telegram_integration.py`:
   - Exercise live boundary crossing: simulated Telegram update -> authorization check -> `run_pi_turn` subprocess execution -> channel response delivery.
4. Record evidence in `tracker/features.yaml` under `F-0046` and verify Level 4 (`INTEGRATED`).
5. Run full guard checks, full tracker verification, and export.
