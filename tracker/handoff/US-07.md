# US-07 handoff - Claude 3.5 Sonnet, 2026-10-27

## Plan (written before coding)
- Implement Telegram Gateway as a ChannelProvider:
  - Register `TelegramGateway` under both `('channel', 'telegram')` and `('channels', 'telegram')` in `ProviderRegistry`.
  - Concrete channel provider methods in `BaseChannelProvider` (non-stub base class).
  - When an incoming message arrives from the paired owner, invoke `run_pi_turn(prompt=message_text, session_id='telegram_<chat_id>')`.
  - Handle Telegram 4096-character limit via paragraph/whitespace splitting helper `chunk_telegram_text(text, max_len=4096)`.
  - Send all chunks to the paired owner via `send_message(chat_id, chunk)`.
  - Filter out group chats, forwards, and inline queries.
  - Reject stranger/unpaired messages with single fixed line `"not configured"` and execute NO Pi turns.
  - Enforce off switch: `locus.channels.telegram.enabled: false` suppresses message processing and returns degraded health check.
- Tests:
  - `tests/unit/test_telegram_gateway.py` covering interface implementation, paired owner turn execution with Pi bridge, chunking, stranger rejection, disabled off-switch, and group/forward filtering.
- Update `tracker/features.yaml` for F-0046 to reach Level 3 (`UNIT_VERIFIED`).

## Config keys and defaults added
- `locus.channels.telegram.enabled`: boolean switch (default True; when false, gateway is disabled and handles no messages).
- `locus.channels.telegram.webhook`: boolean switch (default False; when true, requires `TELEGRAM_WEBHOOK_SECRET`).
- `channels.telegram.allowed_user_id`: numeric Telegram ID of the paired owner.
