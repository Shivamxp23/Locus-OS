# US-49: Memory Queue (Async Job Pipeline)

## Summary
Implements Feature §4.8 `F-0090`: Memory Queue (Async Job Pipeline) — an asynchronous job execution architecture designed to move extraction, scoring, summarisation, and daily digesting off the ingest hot path.

## Key Changes
- **Core Provider & Data Types** (`sidecar/providers/memory_queue.py`):
  - Declares `JobKind` (`extract_chunk`, `append_buffer`, `seal`, `topic_route`, `digest_daily`, `flush_stale`).
  - Declares `JobStatus` (`ready`, `running`, `done`, `failed`).
  - Declares `JobRecord` dataclass matching table `mem_tree_jobs` columns.
  - Declares `MemoryQueueConfig` with worker counts, lease duration (300,000 ms), LLM concurrency semaphore (3 permits), and throttle gating.
  - Defines `BaseMemoryQueueProvider` abstract interface.
- **SQLite Persistence & Worker Pool Engine** (`sidecar/memory_queue.py`):
  - Table `mem_tree_jobs` with partial unique index `(dedupe_key) WHERE status IN ('ready', 'running')`.
  - Duplicate suppression using `INSERT OR IGNORE RETURNING id`.
  - Atomic claim pattern: single `UPDATE ... RETURNING` assigning a unique claim token without select race conditions.
  - Settlement guards: `mark_done` and `mark_failed` enforce claim token verification; stale worker settlements are no-ops.
  - Stale lock recovery: resets expired `running` leases to `ready` based on `claimed_at < now - lock_duration`.
  - Scheduler helpers: `trigger_digest`, `backfill_missing_digests`, `flush_stale_daily`, and `daily_tick`.
  - Worker execution harness with 3-permit LLM semaphore and throttle gating.
- **Sidecar REST Endpoints** (`sidecar/service.py`):
  - Static endpoints registered before parameterized paths:
    - `GET /memory/queue/config`
    - `GET /memory/queue/stats`
    - `GET /memory/queue/jobs`
    - `POST /memory/queue/enqueue`
    - `POST /memory/queue/claim`
    - `POST /memory/queue/settle`
    - `POST /memory/queue/recover_stale`
    - `POST /memory/queue/trigger_digest`
    - `POST /memory/queue/backfill_digests`
    - `POST /memory/queue/flush_stale`
    - `POST /memory/queue/daily_tick`
  - Parameterized endpoint:
    - `GET /memory/queue/jobs/{job_id}`
  - Modular off-switch returning HTTP 503 when disabled or when `locus.memory.queue.workers <= 0`.
- **TypeScript Extension Client** (`locus-extension/src/memory-queue.ts` & `locus-extension/src/index.ts`):
  - `MemoryQueueClient` class providing full typed API for extension consumers.
- **Tests**:
  - `tests/unit/test_memory_queue.py`: 8 unit tests covering deduplication, atomic claims, settlement guards, stale lock recovery, throttle backoff, and daily scheduler ticks.
  - `tests/integration/test_memory_queue_service.py`: 5 integration tests validating FastAPI routes, end-to-end workflows, and 503 off-switch.
  - All test docstrings trace directly to §4.8 lines.
- **Test Attack**:
  - Detached worktree attack in `../verify-tmp` mutating `mark_done` to remove claim_token verification cleanly caught by 3 tests.
