## Plan (written before coding)
- Implement `BaseAntiHallucinationProvider`, `CheckResult`, `FactualClaim`, `BrainErrorLog`, and `GuardMode` in `sidecar/providers/anti_hallucination.py`.
- Re-export anti-hallucination contracts in `sidecar/providers/__init__.py`.
- Implement `AntiHallucinationProvider` in `sidecar/anti_hallucination.py`:
  - STEP 1: Claim Extraction: Parse LLM output for factual statements about user data, completed actions, vault contents, habit logs, task records, and calendar entries using syntactic regexes. Ignore opinions, questions, greetings, caveats.
  - STEP 2: Grounding Verification: Verify each extracted claim against Context Forge retrieval content. If claim has numbers/quantities, strictly verify exact numerical match in context. Compute word overlap ratio.
  - STEP 3: Strict Mode (severity 2): If any ungrounded claim detected, block output, log `BrainErrorLog` with severity=2, return apology reason.
  - STEP 4: Warn Mode (severity 1): Append standard caveat prefix `⚠️ Note: I'm not fully certain about some details. Let me know if anything seems off.` and log severity=1 error.
  - Off switch on `locus.brain.anti_hallucination.enabled` returning 503 or passthrough if mode is `off`.
- Implement TypeScript client component in `locus-extension/src/anti-hallucination.ts` with `AntiHallucinationGuard` and `afterToolCall` hook integration, and re-export in `locus-extension/src/index.ts`.
- Register routes `/guard/check` and `/guard/config` in `sidecar/service.py` with 503 off-switch.
- Unit tests in `tests/unit/test_anti_hallucination.py` and integration tests in `tests/integration/test_anti_hallucination_service.py`.
- Pi table:
  - Need: Real-time hallucination prevention guard verifying LLM claims against assembled context before user sees the turn or after tool call execution.
  - Pi mechanism: Pi has `afterToolCall` hooks and streaming output events, but performs no post-generation factual grounding check, claim verification, caveat injection, or brain error logging.
  - What Locus adds: Stage 10 Anti-Hallucination Guard with dual operational modes (strict block vs warn caveat injection), numerical grounding checks, structured BrainError logging, and modular 503 off-switch.
  - Why Pi's is not enough: Pi passes model output directly to UI; without verification, fabricated task statuses or hallucinated vault records corrupt user trust and state.
