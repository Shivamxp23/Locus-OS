# US-44 handoff - Gemini 3.8 Flash, 2026-10-20

## Plan (written before coding)
- Implement `BaseToolTimeoutBudgetProvider`, `TimeoutAction`, `ToolTimeoutConfig`, `TimeoutResolution`, and `ExecutionBudgetRecord` in `sidecar/providers/tool_timeout_budget.py`.
- Re-export Tool Timeout / Budget provider contracts in `sidecar/providers/__init__.py`.
- Implement `ToolTimeoutBudgetProvider` in `sidecar/tool_timeout_budget.py`:
  - `resolve_timeout`: Computes effective execution timeout in seconds. Handles explicit requested timeouts, per-tool overrides (e.g. bash/terminal 300s, web_search 60s, read_file 30s), system maximum ceiling (3600s), and turn budget remaining limits.
  - `record_execution`: Tracks elapsed execution duration per tool invocation and updates turn elapsed counters.
  - `get_remaining_turn_budget`: Calculates remaining unspent seconds in the active turn.
  - `reset_turn_budget`: Resets elapsed turn time and optionally configures new turn budget limits.
  - Modular off-switch checking `locus.tool_timeout_budget.enabled` and `locus.tools.timeout.enabled`.
- Implement TypeScript client and `withTimeout` wrapper in `locus-extension/src/tool-timeout-budget.ts` and re-export in `locus-extension/src/index.ts`.
- Register routes in `sidecar/service.py`: `/tools/timeout/resolve`, `/tools/timeout/record`, `/tools/timeout/remaining`, `/tools/timeout/reset`, and `/tools/timeout/config` with 503 off-switch.
- Unit tests in `tests/unit/test_tool_timeout_budget.py` and integration tests in `tests/integration/test_tool_timeout_budget_service.py`.
- Pi table:
  - Need: Per-tool execution timeouts, per-turn execution time budgets, and overrun protection.
  - Pi mechanism: Pi tools rely on subprocess wait or raw timeout promises per tool without centralized turn budget enforcement or configurable overrides across external providers.
  - What Locus adds: Derived from OpenHuman `tool_timeout`, Locus provides centralized per-tool timeout configuration, maximum clamping, per-turn budget tracking, and over-budget blocking exposed through Sidecar REST endpoints and a TypeScript client wrapper.
  - Why Pi's is not enough: Pi has no concept of an aggregate turn execution budget across multi-tool invocations, allowing runaway execution across consecutive long-running tool calls.
