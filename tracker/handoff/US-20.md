## Pi Table
| need | Pi mechanism | what Locus adds | why Pi is not enough |
|---|---|---|---|
| Coding harness delegation to external agents (Pi, Claude Code, OpenCode, Antigravity) | Self-coding loop in local workspace | `BaseHarnessProvider`, `HarnessProvider`, `InterHarnessBridge`, task selection matrix, argument construction with permission guards, isolated scratch git worktree lifecycle (`git worktree add/remove`), output/diff capture, and `/harness/*` service endpoints | Pi only operates on its own session in the current directory; it cannot delegate tasks to Claude Code, OpenCode, or Antigravity, does not isolate foreign executions in dedicated scratch git worktrees, and cannot capture structured diffs and files modified from external agents. |

## Plan (written before coding)
- Implement `sidecar/providers/harness.py`:
  - `BaseHarnessProvider` abstract interface declaring `select_harness()`, `format_command_args()`, and `execute_delegation()`.
  - Data transfer types: `HarnessType`, `TaskBrief`, `DelegationResult`.
- Implement `sidecar/harness/delegation.py`:
  - `HarnessProvider` implementing `BaseHarnessProvider`.
  - Harness selection matrix: Antigravity for high complexity, Claude Code for autonomous multi-step, OpenCode for quick fixes, and Pi as default fallback.
  - Command argument builder with strict rejection of `--dangerously-skip-permissions` per 10-security.md S-3.
  - Scratch worktree creation (`git worktree add --detach <scratch_dir> HEAD`), execution in scratch directory, `git diff HEAD` and `git diff --name-only HEAD` collection, and guaranteed worktree cleanup.
  - Modular off-switch checking `locus.harness.enabled`.
- Implement `sidecar/inter_harness_bridge.py`:
  - `InterHarnessBridge` connecting agent turns and router to the active harness provider.
- Update `sidecar/service.py`:
  - Register `/harness/delegate` and `/harness/harnesses` endpoints.
  - Modular off-switch returning 503 `{"disabled": "locus.harness.enabled"}` when disabled per SPEC §03 line 35.
- Tests in `tests/unit/test_harness_delegation.py` and `tests/integration/test_harness_service.py`:
  - Unit tests for interface adherence, harness selection, command formatting, permission guard enforcement, scratch worktree creation and cleanup, subprocess error handling, modular off-switch, and provider swapping.
  - Integration tests for FastAPI endpoints and 503 off-switch response.
