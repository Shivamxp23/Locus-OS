## Plan (written before coding)
- Implement tree-structured JSONL v3 sessions in `sidecar/sessions/session_manager.py` with support for entry types (`message`, `tool_call`, `tool_result`, `compaction_summary`, `branch_summary`, `metadata`, `system_event`, `checkpoint`, `marker`).
- Implement `fork_session(parent_session_id, fork_point, summary)` copying entries up to fork_point and appending `BranchSummaryEntry`.
- Implement `resume_session(session_id)` replaying entries, retrieving compaction entries, and rebuilding context (summaries first, then recent messages).
- Implement `TelegramSessionBridge` maintaining persistent SQLite/PostgreSQL `telegram_sessions` table mapping Telegram chat IDs to session IDs, injecting user messages, invoking responder, and persisting responses.
- Implement session exports in `sidecar/session_export.py` supporting Markdown transcripts, structured JSON, and raw JSONL v3.
- Implement `BaseSessionManagementProvider` and `DefaultSessionManagementProvider` in `sidecar/providers/session_management.py` and register in provider registry.
- Implement TypeScript contract in `locus-extension/src/session-bridge.ts`.
- Mount FastAPI endpoints in `sidecar/service.py`:
  - `GET /sessions/config`
  - `POST /sessions/create`
  - `GET /sessions/{session_id}`
  - `POST /sessions/{session_id}/fork`
  - `POST /sessions/{session_id}/resume`
  - `POST /sessions/{session_id}/export`
  - `POST /sessions/telegram/bridge`
  - Modular off-switch returning HTTP 503 if `locus.session_management.enabled` or `locus.sessions.enabled` is False.
- Write unit tests in `tests/unit/test_session_management.py` and integration tests in `tests/integration/test_session_management_service.py`.
- Pi table:
  - Need: Cross-surface session management supporting tree branching, compaction context resumption, multi-format export, and persistent Telegram chat-to-session bridge.
  - Pi mechanism: `packages/coding-agent/src/core/session-manager.ts` handles local CLI session files and branching within Pi's agent loop.
  - What Locus adds: Full Python sidecar `SessionManager` & `TelegramSessionBridge` with SQLite `telegram_sessions` mapping, multi-format export (`sidecar/session_export.py`), `SessionManagementProvider` with HTTP API endpoints and 503 off-switch, and TypeScript contract in `locus-extension/src/session-bridge.ts`.
  - Why Pi's is not enough: Pi has no Telegram channel bridge, no sidecar REST interface, no cross-surface Telegram chat mapping, and no standalone multi-format export utility outside Pi's interactive CLI.

## Security (anything found, even if outside this story)
- Binding plain HTTP to 0.0.0.0 remains strictly blocked per 10-security.md and D-13; sidecar service binds exclusively to loopback (127.0.0.1).
- Session IDs use cryptographically secure uuid4 strings preventing directory traversal.
