## Plan (written before coding)
- Enhance `sidecar/registry.py`:
  - `ProviderRegistry.register(area, name, provider_cls)` registers providers under (area/interface, name).
  - `ProviderRegistry.get_active_provider(area, feature, default_name)` determines active provider via `locus.<area>.<feature>.provider` or `locus.<area>.provider`.
  - Enforce off-switch behavior:
    - `check_route_allowed(config_key)`: returns `(503, {"disabled": "<config key>"})` when false, `None` when allowed.
    - `register_tool(tool_name, config_key, tool_fn)`: tool is suppressed and not registered when false.
    - `schedule_job(job_id, config_key, job_fn)`: job is suppressed and not scheduled when false.
  - Health check: `health_check_all()` iterates through registered providers and calls `health_check()`.
- Enhance `locus-extension/src/registry.ts`:
  - Mirror Python `ProviderRegistry` methods in TypeScript.
  - Provide `getActiveProvider(area, feature, defaultName)`.
  - Provide `registerTool(toolName, configKey, toolDef)` enforcing off-switch.
  - Provide `checkRouteAllowed(configKey)` returning 503 structure when disabled.
- Unit and Integration tests:
  - `tests/unit/test_registry.py` (unit tests for singleton, active selection, off-switch for routes/tools/jobs, provider swap, and health check).
  - `tests/unit/test_registry.test.ts` (Node test runner verifying TypeScript registry off-switch and active selection).
  - `tests/integration/test_provider_modularity.py` (crosses component and process boundaries, testing dynamic swap via config file on disk and cross-language execution).

## Config keys and defaults added
- `locus.<area>.<feature>.provider`: Active provider name for a specific feature.
- `locus.<area>.provider`: Active provider fallback name for an entire area.
- `locus.<area>.<feature>.enabled`: Boolean switch for feature (defaults to True; when false, routes answer 503, tools are unregistered, jobs are unscheduled).
