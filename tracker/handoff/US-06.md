# US-06 handoff - Gemini, 2026-10-15

## Plan (written before coding)
1. Implement canonical `ProviderRegistry` and `get_registry()` in `sidecar/registry.py` following Universal Provider Pattern (`docs/agent/03-modularity.md`).
2. Implement identical `ProviderRegistry` and `get_registry()` / `getRegistry()` in `locus-extension/src/registry.ts`.
3. Support provider registration under `(interface, name)` with default provider resolution, explicit provider resolution, and dynamic resolution based on `locus.<area>.<feature>.provider`.
4. Enforce strict "off" behavior:
   - HTTP routes answer 503 with `{"disabled": "<config key>"}` (via `route_guard` decorator and `disabled_http_response`).
   - Tools associated with disabled features are suppressed and excluded from `get_active_tools()`.
   - Scheduled jobs associated with disabled features are suppressed and excluded from `get_active_jobs()`.
   - Direct `get()` on a disabled feature raises `FeatureDisabledError`.
5. Implement health check interface `BaseProvider.health_check() -> {status, latency_ms, error}` and `registry.health_check_all()`.
6. Write unit tests in `tests/test_provider_registry.py` proving off behavior (HTTP 503, tools suppressed, jobs suppressed), provider swap by config without code edit, health checks, and TypeScript parity.
7. Write integration tests in `tests/test_registry_integration.py` proving HTTP service boundary crossing and Python/TypeScript cross-runtime synchronization over a shared `config.yaml`.
8. Register evidence in `tracker/features.yaml` under `F-0125` and verify Level 4 (`INTEGRATED`, 85%).
9. Run full guard checks, tracker verification, and Excel export.
