## Plan (written before coding)
- Implement `BaseToolCallValidationProvider`, `ToolCallGuardrailConfig`, `ToolCategory`, `ValidationAction`, `ValidationDecision`, and `ValidationObservation` in `sidecar/providers/tool_call_validation.py`.
- Re-export Tool Call Validation provider contracts in `sidecar/providers/__init__.py`.
- Implement `ToolCallValidationProvider` in `sidecar/tool_call_validation.py`:
  - `validate_schema`: Validate parameter types, required fields, and enum boundaries against tool schemas without raising unhandled exceptions.
  - `before_call`: Guardrail checks evaluating schema errors, per-turn caps (searches/subagents), repeated exact failure circuit breaking (warn at 2, block at 4), cumulative same-tool failure halts (warn at 3, halt at 6), and multi-turn alternating cycle detection.
  - `observe_call`: Track execution outcomes, record failure counts, detect idempotent stall streaks (notice and duplicate stubbing at threshold 3), and clear failure counts upon mutating tool successes.
  - `reset_for_turn`: Flush turn-local streak counters and cycle history.
  - Modular off-switch checking `locus.tool_call_validation.enabled`, `locus.tools.validation.enabled`, and `locus.brain.tool_call_validation.enabled`.
- Implement TypeScript client in `locus-extension/src/tool-call-validation.ts` and re-export in `locus-extension/src/index.ts`.
- Register routes `/tools/validate`, `/tools/observe`, `/tools/reset`, and `/tools/validation/config` in `sidecar/service.py` with 503 off-switch and persistent provider instance.
- Unit tests in `tests/unit/test_tool_call_validation.py` and integration tests in `tests/integration/test_tool_call_validation_service.py`.
- Pi table:
  - Need: Pre-call parameter validation and runtime loop guardrails (repeated failure circuit breaking, stall guard duplicate stubbing, alternating cycle detection).
  - Pi mechanism: `packages/coding-agent/src/core/tools/tool-definition-wrapper.ts:8-58` wraps `ToolDefinition` into `AgentTool` with context factories, but provides no loop detection, no identical-call stall guard, no repeated failure circuit breaker, and no cycle detection.
  - What Locus adds: Stolen from Hermes `tool_guardrails.py`, Locus adds full loop detection, repeated failure blocking, identical call notice/stubbing, cycle history tracking, parameter schema validation, and per-turn caps, exposed via Sidecar REST endpoints and TypeScript client wrapper.
  - Why Pi's is not enough: Pi's wrapper is purely an interface bridge; when an LLM enters an infinite failure loop (e.g. running the same failing command repeatedly or hammering a read-only endpoint without progress), Pi runs until context or budget is exhausted.
