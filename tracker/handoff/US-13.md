# US-13 handoff - Claude 3.5 Sonnet, 2026-11-12

## Plan (written before coding)
- Implement `locus_cli/doctor.py`:
  - `DiagnosticResult`: holds check status, message, optional remediation advice, and criticality flag; formats output line as `[PASS] <name>: <message>` or `[FAIL] <name>: <message> -> Fix: <remediation>`.
  - Diagnostics:
    - `check_python`: verifies Python >= 3.10.
    - `check_node`: verifies Node.js >= 18.
    - `check_git`: verifies Git presence in PATH.
    - `check_docker`: checks Docker CLI and daemon response.
    - `check_port_free`: checks loopback port availability (e.g. 8420 for sidecar).
    - `check_vault_writability`: tests directory creation and probe file write/unlink.
    - `check_environment_keys`: tests `.env` existence and `LOCUS_HOME` presence.
    - `check_sidecar_health`: tests HTTP GET to `127.0.0.1:8420/health`.
    - `check_registered_providers`: queries `get_registry().health_check_all()` for modular health.
  - CLI runner: `run_doctor` and `main` with `--vault-dir`, `--env-file`, `--check-sidecar`, `--strict`, and `--json`.
- Update launchers `locus.bat` and `locus.cmd`:
  - Support `doctor` command: dispatches to `py -3 -m locus_cli.doctor`.
  - Support `setup pi` command: passes directly to Pi CLI `packages\coding-agent\dist\cli.js` (R5).
  - Default pass-through to Pi TUI if available, otherwise doctor.
- Tests in `tests/unit/test_doctor.py`:
  - `test_doctor_diagnostics_formatting_and_checks`: validates format strings and system checks.
  - `test_doctor_vault_and_env_checks`: validates directory writability and env file parsing.
  - `test_doctor_exit_codes_and_criticality`: validates exit codes on pass and critical failures.
  - `test_launcher_doctor_dispatch_and_pi_passthrough`: validates dispatch and Pi pass-through commands.
  - `test_doctor_cli_run`: verifies subprocess CLI run with `--vault-dir` and `--env-file`.
