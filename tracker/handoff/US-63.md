- Re-export symbols in `sidecar/skills/__init__.py` and `sidecar/providers/__init__.py`.
- Implement TypeScript contract `SkillMarketplaceClient` and `SkillManifest` in `locus-extension/src/skills/marketplace.ts`.
- Mount FastAPI endpoints in `sidecar/service.py`:
  - `GET /skills/marketplace/sources`: returns dictionary of supported marketplace indices and URLs.
  - `GET /skills/marketplace/manifest`: fetches remote skill manifest and validates prerequisites.
  - `POST /skills/marketplace/install`: downloads and installs skill bundle into local skills repository.
  - `GET /skills/marketplace/installed`: lists currently installed skills.
  - Off-switch returning HTTP 503 if marketplace is disabled.
- Write unit tests in `tests/unit/test_skill_marketplace.py` and integration tests in `tests/integration/test_skill_marketplace_service.py`.
- Pi table:
  - Need: Multi-source skill discovery, manifest validation, dependency/environment verification, and automated skill installation (`pi-gallery`, `anthropic`, `claude-skills`, `openai`, `lobehub`).
  - Pi mechanism: `packages/agent/src/skills/` (and `agent-session.ts`) provides static local discovery of `SKILL.md` bundles in workspace and global directories, but lacks remote marketplace querying, multi-source index resolution, and automated dependency installation.
  - What Locus adds: Full `SkillMarketplaceEngine` in Python sidecar and TypeScript extension client (`locus-extension/src/skills/marketplace.ts`) supporting multi-index registry resolution (`INDEX_URLS`), manifest validation (`SkillManifest`), env var dependency checks, and REST endpoints with 503 off-switch.
  - Why Pi's is not enough: Without a multi-source marketplace client, users must manually locate, download, verify dependencies for, and copy skill repositories into disk directories.
